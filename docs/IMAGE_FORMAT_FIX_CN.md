# 图片输出格式校验修复（2026-09-26）

## 原因

自动探测导入的基础能力没有声明 `output_formats` 和默认输出格式，但前端会在
未声明格式时仍发送 `output_format: png`。后端按允许列表严格校验，因而返回 400。
旧界面将其显示为 `The image job is invalid.`，任务尚未发送上游。

## 修复内容

- 新导入模型的基础能力声明 `output_formats: ["png"]`、
  `defaults.output_format: "png"`。
- 前端只发送能力中明确允许的输出格式。旧模型没有声明格式时，省略该可选参数。
- 后端继续严格校验，返回具体的 `job_parameter_output_format` 等原因；
  前端按界面语言显示对应提示，不用放宽校验来掩盖不支持的参数。
- 经正常管理员接口修复已有 `gpt-image-2.5-sunburst` 和 `gpt-image-2.5`。
  配置版本 10→11，仅补齐上述两个字段；保留模型启停、张数、图片编辑和其他设置。
  更新带版本锁与审计，没有直接修改数据库。
- 不修改用户原任务、不改变 Key 绑定、不修改主站分组。

配置修复备份：`state/operator/format-fix-20260926/policy-before.json` 与
`policy-after.json`。回退时应读取最新策略并通过管理页只调整目标字段；
不要直接覆盖整份历史策略，以免覆盖其他管理员后续修改。

## 你如何验证

1. 刷新创作台页面，进入原项目。
2. 选择可用 Key 与 `gpt-image-2.5-sunburst`，选择 1:1 尺寸。
3. 文生图可按当前模型限制选择 7 张。先确认没有重复运行中的原任务，再手动重试一次。
4. 任务应进入生成阶段并返回图片。不要连续点击重试创建重复任务。
5. 如发生新的错误，记录具体提示；上游权限、额度或编辑能力错误不能靠补输出格式解决。
   本次没有开启该模型的图片编辑能力。

新添加模型时，进入“模型管理 → 添加模型 → 选择 Key → 选择探测模型”，
在高级参数中可检查 PNG 允许列表与默认值。保存后回创作台使用。
