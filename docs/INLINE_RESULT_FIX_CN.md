# 图片响应同时包含 Base64 和 URL 的修复

## 故障原因

部分上游返回 `data[].b64_json` 与 `data[].url` 两个字段。旧创作台只要看到非空 URL 就拒绝整个条目，随后显示 `invalid_official_result`，即使上游已经生成图片并计费。

2026-09-27 的正式 worker 任务 `job_84312d9943b798460474c9a770b55f84` 复现了该问题。响应抓包虽有缺包，但完整保留了非空 URL 字段及 Base64 字段开头，足以定位无条件拒绝分支；通过返回链接下载的图片也完整解码成功。证据位于 `state/operator/snow-palace-worker-20260927/`。

## 修复行为

创作台优先解析内联 `b64_json`，忽略额外 URL。不会因为上游附带下载链接而拒绝正常图片，也不会访问该链接。

原有约束继续生效：结果非空、输出数量不超过请求、Base64 严格可解码、单张不超过 32 MiB，以及资产保存时的实际图片内容校验。只有 URL 没有 Base64 的响应仍不支持；此修复不引入远程图片下载。
